# Contributing to RubyNDS

Code contributions are welcomed and encouraged. At the moment, I (gavff) intend to soley write and contribute to documentation.

## LLMs and Spam

You are allowed to use LLMs in whatever capacity, **except for writing issues.** There is an expectation of human discourse. LLM generated code does not need to be disclosed, but you must
have some level of understanding the purpose of it, why it's written the way it is, and what exactly it's doing.

This is absolutely not a vibecoded project, and I intend on keeping it that way, respectfully.

Untested code, repeated out of scope requests, arguments, may result in a ban.

## The "Spirit" of the Project

As stated in the main [README](./README.md), the point of RubyNDS is not necessarily to be a framework, or an engine, or anything of that sort. But rather a means of developing for hardware using a
more fun language. As well as being able to easily choose how deep you want to dive in. You could jump straight into C and write low-level Ruby API implementations, or be the one to monkey patch
those low-level APIs in Ruby, make your own mrbgems, or better yet just stick with the high-level Ruby API.

That being said, although you will find examples of C doing work that could have been delegated to Ruby. We do not want RubyNDS to just be another SDK where everything is written in C, but with a
pinch of Ruby in it. Changes that attempt to move away pieces from Ruby without a good reason will not be approved. This however may be up to interpretation.
